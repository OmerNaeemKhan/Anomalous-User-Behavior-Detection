## Anomalous User Behavior in Authentication Logs

# 1. Overview

SQL is an important component of this project because authentication logs are structured security data that need to be stored, queried, filtered, and analyzed efficiently.

6. Total Authentication Events

A basic SQL query can determine the total number of authentication records.

SELECT COUNT(*) AS total_events
FROM authentication_logs;

This provides a high-level view of the dataset size.

In a real security environment, this type of query could be used to measure:

Daily authentication volume
Weekly authentication volume
Monthly authentication volume
Changes in login activity over time

Large or unexpected increases in authentication volume may indicate:

Automated login attempts
Credential attacks
System misuse
Unusual user activity
7. Successful and Failed Logins

Authentication success and failure rates are important security indicators.

Example query:

SELECT
    success,
    COUNT(*) AS event_count
FROM authentication_logs
GROUP BY success;

The results can be interpreted as:

success = 1 → Successful Login
success = 0 → Failed Login

Failed authentication attempts are particularly important because repeated failures may indicate:

Incorrect credentials
Password guessing
Brute-force attacks
Credential stuffing
Unauthorized access attempts
8. User Activity Analysis

SQL can identify users with the highest number of authentication events.

Example query:

SELECT
    username,
    COUNT(*) AS login_count
FROM authentication_logs
GROUP BY username
ORDER BY login_count DESC;

This helps identify users with unusually high activity.

High authentication volume does not automatically indicate malicious behavior. However, it may be useful for investigation when combined with other indicators such as:

Failed login attempts
New IP addresses
Unusual devices
Unusual locations
AI anomaly scores
9. Failed Login Analysis by User

A more targeted security query can identify users with repeated failed authentication attempts.

SELECT
    username,
    COUNT(*) AS failed_login_count
FROM authentication_logs
WHERE success = 0
GROUP BY username
ORDER BY failed_login_count DESC;

This query helps identify accounts with repeated failures.

Possible reasons include:

Users forgetting passwords
Misconfigured applications
Automated scripts
Brute-force attacks
Unauthorized access attempts

These results should be investigated together with other behavioral indicators.

10. Authentication Activity by Location

SELECT

11. Authentication Activity by Device

12. Anomalous Events by User

The dataset contains an is_anomaly field that can be used for analysis and comparison.

Example query:

SELECT
    username,
    COUNT(*) AS anomaly_count
FROM authentication_logs
WHERE is_anomaly = 1
GROUP BY username
ORDER BY anomaly_count DESC;

This query identifies users associated with the largest number of labeled anomalous events.

These results are useful for:

Security investigations
Comparing labeled anomalies with AI predictions
Identifying users requiring additional review
13. User Authentication Summary

A useful SQL query can combine multiple authentication indicators.

SELECT
    username,
    COUNT(*) AS total_logins,
    SUM(CASE WHEN success = 1 THEN 1 ELSE 0 END) AS successful_logins,
    SUM(CASE WHEN success = 0 THEN 1 ELSE 0 END) AS failed_logins,
    SUM(CASE WHEN is_anomaly = 1 THEN 1 ELSE 0 END) AS labeled_anomalies
FROM authentication_logs
GROUP BY username
ORDER BY failed_logins DESC;

This provides a more complete user activity profile.

For each user, the analysis can show:

Total login attempts
Successful logins
Failed logins
Labeled anomalous events

This type of summary is useful because cybersecurity investigations should evaluate multiple signals rather than relying on only one metric.

14. Location and Anomaly Analysis

15. Device and Anomaly Analysis
